**This file is a pointer. The contract lives in `RealityEngine_CI`.**

    RealityEngine_CI/docs/ARBITER_CONTRACT.md

Do not edit this file, and do not copy the contract back into this repository.
Edit the master in `RealityEngine_CI` instead.

## Why this is a pointer

This repository implements the contract — `reality::OutputArbiter` for the
per-machine fold, and `resolve_all` in `src/arbiter.cpp` for the per-cell
resolution — but it does not define it. The contract binds four runtimes, and
its §8 acceptance test is byte equivalence across them. A definition that one
implementation owns is not a definition the other three can be measured
against.

The master carried no pointer here until now. That is the failure one step
before drift: nothing in this repository named the contract, so the natural
repair for "the arbiter needs describing where it is implemented" was a local
description, and a local description becomes a second master. The C++ engine is
where that pressure is highest, because it is the implementation the others are
compared to.

## What this repository owns

The C++ implementation, its tests, and its performance characteristics.
`ARBITER_ARCHITECTURE.md` in this repository is a pointer for the same reason
and to the same place; it disambiguates the three distinct things this system
calls "arbitration" — `outputMergeTransformation`, `arbiterRule`, and the cell
arbitration registry.

## Citations

References elsewhere in this repository are prose citations of the form
`ARBITER_CONTRACT.md §5` and remain correct. A citation that also names a
repository is the one that goes stale: `docs/API_EQUIVALENCE.md` named
`RealityEngine_Machines` as the contract's home after the master had moved to
`RealityEngine_CI`, and `RealityEngine_Machines/docs/ARBITER_CONTRACT.md` is
itself a pointer. Cite the section, not the repository.

`RealityEngine_CI/scripts/check-surface-specs.sh` enforces that this file stays
a pointer.
